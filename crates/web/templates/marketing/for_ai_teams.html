Failure modes Sentinel was designed for

If you've shipped one agent, you've seen one of these.

The infinite tool loop

Agent calls web_search("X"), decides the answer isn't there, calls web_search("X") again. Sentinel sees five-in-a-row and stops it.

The midnight cost spiral

A misconfigured retry storm sends 200 requests per second to a 200k-context model. Sentinel hits a velocity cap and pauses the agent.

The session that never converges

An agent burns through $30 of context fighting itself. Hard cost cap fires, incident opens, the session ends with a logged reason.

The prompt-injection escape

A tool result tries to redirect the agent. You see the span trail in the dashboard, can replay it, can pin policies against it.

What you get

Observability that's already a kill switch.

  • Spans for every LLM call, tool call, and reasoning step.
  • Token and dollar totals per agent, per session, per day.
  • Configurable policies: cost cap, velocity, repetition.
  • SSE stream to sidecars so kills land in milliseconds.
  • Incident dashboard with replay-ready span timelines.
